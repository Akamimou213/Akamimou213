Appfound explainer: four directions

One idea: your ads work, your users leak between the install and the payment, and Appfound plugs every leak, then feeds and scales only what pays. Four ways to show it, side by side. This page is the decision log. The winner is outlined.

A · Winner

The leak track

  • Users are dots running along the site's own funnel strip: Ad, Store, Onboarding, Paywall, Paying.
  • Leaks open, users fall out in coral; few reach Paying. Each service then lands on the stage it fixes.
  • Grammar from ref A (a ball lays a track of labelled blocks, cards hang under them) and ref B (a scrolling pill list for the 90 days).

Why it wins: it is the real model, not a metaphor. One object (the funnel) carries problem, services, turn and payoff, and it matches the site's hero.

B

The bucket

  • Ad spend pours into a bucket with holes; services patch holes; the bucket fills.
  • Uses the site's "How it works" canvas animation.

Rejected: one container can't show where each leak is or which service fixes which stage, and it can't carry the 90-day process.

C

Pill roster

  • Ref B played straight: the wordmark on the left, services as pills scrolling on the right, white ground.

Rejected as the whole film: it's elegant, but it has no problem and no cause and effect. Kept as the device for the 90-day act.

D

Dashboard truth

  • An Ads Manager table where CPI looks great and revenue doesn't, then the same table after Appfound.

Rejected: it needs result numbers, which the brief rules out, and the site's real numbers would turn it into a results film.
