# Storyboard variants (gate G4, when the direction is open)

After the assets and the reference scan, propose **three** genuinely different films for the same brief, not three
palettes of one idea. For each one, give:

- **Name + logline:** one sentence, plus the turn or the joke.
- **Grammar:** which reference moves it borrows (cuts vs one continuous shape, type pairing, accent element, camera).
- **Beat sheet:** 5–8 rows on the BPM grid (time · picture · words on screen · real asset used).
- **Hero moment:** the single frame people will screenshot.
- **Real assets it needs:** and whether they're already captured.
- **Risk:** what could look generic or break at phone size; production cost (light / medium / heavy).

Archetypes to start from (pick the three that fit the subject and the goal):
1. **Reference remake.** The reference's pacing and transitions, rebuilt with the subject's real assets and copy.
2. **One-shape morph.** A single element becomes logo → button → input → answer → loader → … → logo, driven by
   real interactions; seamless loop. Best for products with a clear flow.
3. **Kinetic type + real UI.** The problem in ≤5 huge words, the product assembles piece by piece, three features as
   cursor/finger moments, one verified number, logo + CTA. The default for launches and ads.
4. **App in hand.** Screen recordings in an official device frame, taps on the beat, store rating or metric with
   source, end card with official store badges. For mobile apps and UA.
5. **Manifesto.** Type-only brand film: one sentence per beat, accent words in italics, the brand's real element
   travelling between lines. For brands without product UI.
6. **Data or geography.** The subject's real footprint or the key number on a map or chart, sourced on screen.
   Only with verified data.
7. **Showreel montage.** A new technique every 2–4 s, each cut on a musical hit, signature move last. For people and studios.

For ads, also propose the **hook variants** to test (B, C) that change only the first 1–2 s.

End with a recommendation and why. Once the user picks, render **one still per scene** for that variant as a contact
sheet before animating anything.
